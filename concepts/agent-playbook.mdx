Every `kiwifs init` template except `blank` ships a few agent-facing files beside your pages. An agent loads them with one call to `kiwi_context` and knows the layout, the frontmatter conventions, and the house rules before it writes anything.

## The files

| File | Purpose | Who edits it |
| --- | --- | --- |
| `SCHEMA.md` | Folder layout, frontmatter fields, naming conventions | You, per knowledge base |
| `.kiwi/playbook.md` | Step-by-step tool sequences for common operations | You; the template provides a starting point |
| `.kiwi/rules.md` | Always and never rules for every connected agent | You, with the CLI or the API |
| `index.md` | Entry page that links to every section | Agents keep it current |
| `log.md` | Append-only record of changes (`memory` template) | Agents append to it |

`kiwifs init` copies the template's playbook to `.kiwi/playbook.md`, which is the copy `kiwi_context` serves. `.kiwi/playbook.md` and `.kiwi/rules.md` are the only `.kiwi/` files reachable through the file API.

## Load context in one call

<Tabs>
  <Tab title="MCP">
    Call `kiwi_context` with no arguments. It returns the schema, playbook, index, and rules as one document. Agents should call it first when they connect.

    The schema alone is also available as the read-only resource `kiwi://schema`.
  </Tab>
  <Tab title="REST">
    ```bash Terminal
    curl 'http://localhost:3333/api/kiwi/context'
    ```

    ```json
    {
      "schema": "# Schema\n...",
      "playbook": "# Playbook\n...",
      "index": "# Index\n...",
      "rules": "# Agent Rules\n..."
    }
    ```

    A missing file comes back as an empty string.
  </Tab>
</Tabs>

## Typical operations

Each template's playbook spells out its own sequences. These are the common shapes.

<AccordionGroup>
  <Accordion title="Ingest: add a new source">
    ```text
    kiwi_context
    kiwi_search("authentication")                 # update instead of duplicating
    kiwi_write("pages/auth.md", content, provenance="ingest:rfc-6749")
    kiwi_read("index.md")
    kiwi_write("index.md", updated_index, if_match=etag)
    kiwi_append("log.md", "- added pages/auth.md")
    ```
  </Accordion>
  <Accordion title="Query: answer a question">
    ```text
    kiwi_brief("how does auth work?")             # one token-budgeted pack
    kiwi_read("pages/auth.md")                    # if you need the whole page
    ```
  </Accordion>
  <Accordion title="Remember: record an observation">
    ```text
    kiwi_remember(content, scope="user:alice")   # writes episodes/<date>/<id>.md
    ```
  </Accordion>
  <Accordion title="Consolidate: fold episodes into durable pages">
    ```text
    kiwi_memory_report
    kiwi_read("episodes/2026-05-21/run-7f3a.md")
    kiwi_write("pages/topic.md", merged_content)  # with merged-from in frontmatter
    ```
  </Accordion>
  <Accordion title="Restructure: move or merge pages">
    ```text
    kiwi_refactor_plan(manifest)                  # preview and digest, nothing written
    kiwi_refactor_apply(manifest, digest)         # one commit, links kept intact
    ```
  </Accordion>
  <Accordion title="Audit: check health">
    ```text
    kiwi_lint
    kiwi_health_check("pages/auth.md")
    kiwi_analytics
    ```
  </Accordion>
</AccordionGroup>

## Rules

`.kiwi/rules.md` holds rules that apply to every agent, such as "search before creating a page" or "never store secrets". `kiwi_context` includes it, so MCP agents get it automatically. For agents that read rules from their own config, export it.

```bash Terminal
kiwifs rules                                          # print the rules
kiwifs rules edit                                     # open in $EDITOR
kiwifs rules export --format claude                   # print in a harness format
kiwifs rules sync --format cursor --output .cursor/rules/kiwi.md
kiwifs rules sync --format skill                      # writes .cursor/skills/team-wiki/SKILL.md
```

Formats are `cursor`, `claude`, `agents`, `openclaw`, and `skill`. `sync` needs `--output` for every format except `skill`. Add `--remote http://host:3333` to read the rules from a running server instead of the local file.

Over REST, `GET /api/kiwi/rules` reads the rules (add `format=` for an export) and `PUT /api/kiwi/rules` replaces them. See [Utilities API](/api/utilities#rules-file).

## Provenance on writes

Record which run produced a page. KiwiFS appends an entry to its `derived-from` frontmatter.

<CodeGroup>

```bash REST
curl -X PUT 'http://localhost:3333/api/kiwi/file?path=pages/auth.md' \
  -H 'X-Actor: agent:researcher' \
  -H 'X-Provenance: run:run-249' \
  --data-binary @auth.md
```

```text MCP
kiwi_write("pages/auth.md", content, actor="agent:researcher", provenance="run:run-249")
```

</CodeGroup>
