KiwiFS ships a built-in MCP server. Agents get the same operations as the REST API and web UI — read, write, search, query, restructure — as typed tools, and every write goes through the same pipeline (git commit, index update, live events).

## Choose a mode

The MCP server runs with one of two backends and one of two transports.

| | stdio (default) | Streamable HTTP |
| --- | --- | --- |
| **In-process** (`--root`) | `kiwifs mcp --root ~/knowledge` | `kiwifs mcp --root ~/knowledge --http` |
| **Proxy** (`--remote`) | `kiwifs mcp --remote http://localhost:3333` | `kiwifs mcp --remote http://localhost:3333 --http` |
| **Built into the server** | — | `kiwifs serve` exposes `/mcp` on its own port |

- **In-process** opens the directory directly. Use it for a single local agent.
- **Proxy** talks to a running KiwiFS server over REST, so the agent shares the server's index, live events, and auth. Use it when the web UI or other agents work on the same knowledge base.
- **`kiwifs serve`** always mounts Streamable HTTP MCP at `/mcp` on the main port, next to the REST API. No extra process or flag is needed.

```bash Terminal
# In-process over stdio
kiwifs mcp --root ~/knowledge

# Proxy to a running server, with an API key
kiwifs mcp --remote https://kiwi.example.com --api-key $KIWI_API_KEY

# Proxy to a non-default space
kiwifs mcp --remote https://kiwi.example.com --api-key $KIWI_API_KEY --space docs

# Standalone Streamable HTTP on port 8181 (endpoint /mcp, health check /health)
kiwifs mcp --root ~/knowledge --http --port 8181
```

`--root` and `--remote` are mutually exclusive, and exactly one is required. `--space` only applies with `--remote`. `--port` (default `8181`) requires `--http`. See [`kiwifs mcp`](/cli/commands#mcp) for every flag.

### Authentication

- **Proxy mode** sends `--api-key` to the server as `Authorization: Bearer <key>`.
- **HTTP transport** requires `Authorization: Bearer <key>` when the knowledge base's `.kiwi/config.toml` sets `[auth] type = "apikey"`. The key is `[auth] api_key`. Without API-key auth, the HTTP endpoint is open.

<Warning>
Put remote HTTP MCP behind TLS, and enable API-key auth before exposing it beyond localhost. MCP tools can write, delete, and restructure pages.
</Warning>

## Connect a client

<Tabs>
<Tab title="Claude Code">
```bash Terminal
# Local, in-process
claude mcp add kiwifs -- kiwifs mcp --root /path/to/knowledge

# Running KiwiFS server, over HTTP
claude mcp add --transport http kiwifs http://localhost:3333/mcp \
  --header "Authorization: Bearer $KIWI_API_KEY"
```

To share the setup with your team, commit a `.mcp.json` at the project root with the same `mcpServers` block shown in the Cursor tab.
</Tab>
<Tab title="Claude Desktop">
Edit `claude_desktop_config.json` (macOS: `~/Library/Application Support/Claude/`, Windows: `%APPDATA%\Claude\`).

```json claude_desktop_config.json
{
  "mcpServers": {
    "kiwifs": {
      "command": "kiwifs",
      "args": ["mcp", "--root", "/path/to/knowledge"]
    }
  }
}
```

Use an absolute path to the `kiwifs` binary if Claude Desktop cannot find it on `PATH`.
</Tab>
<Tab title="Cursor">
Add to `.cursor/mcp.json` (project) or `~/.cursor/mcp.json` (global).

```json .cursor/mcp.json
{
  "mcpServers": {
    "kiwifs": {
      "command": "kiwifs",
      "args": ["mcp", "--remote", "http://localhost:3333", "--api-key", "kiwi_sk_..."]
    }
  }
}
```
</Tab>
<Tab title="Windsurf">
Add to `~/.codeium/windsurf/mcp_config.json`.

```json mcp_config.json
{
  "mcpServers": {
    "kiwifs": {
      "command": "kiwifs",
      "args": ["mcp", "--root", "/path/to/knowledge"]
    }
  }
}
```
</Tab>
<Tab title="Any HTTP client">
Point the client at the Streamable HTTP endpoint and pass the API key as a bearer token.

```json mcp.json
{
  "mcpServers": {
    "kiwifs": {
      "url": "http://localhost:3333/mcp",
      "headers": { "Authorization": "Bearer kiwi_sk_..." }
    }
  }
}
```
</Tab>
</Tabs>

<Tip>
For KiwiFS Cloud workspaces, `kiwifs connect <workspace>` prints or writes this config for you. See [KiwiFS Cloud](/guides/cloud).
</Tip>

## First calls

A good session starts with `kiwi_context`. It returns the schema, agent playbook, index, and rules in one call. From there:

1. Find pages with `kiwi_brief` (one token-budgeted context pack) or `kiwi_search_hybrid`.
2. Skim with `kiwi_peek` before paying for a full `kiwi_read`.
3. Write with `kiwi_write`, passing `if_match` (the ETag from `kiwi_read`) so you never overwrite someone else's edit.
4. Verify with `kiwi_lint`.

Write tools accept an optional `actor` (default `mcp-agent`) that is recorded in the git commit.

## Tool reference

The server registers **78 tools**. Every name is invoked exactly as listed. Parameters marked with `*` are required.

| --- | --- | --- |
| `kiwi_read` | Read a page, optionally resolving wiki links. | `path`*, `resolve_links`, `metadata_only`, `if_not_etag` |
| `kiwi_write` | Create or overwrite a page as one git commit. | `path`*, `content`*, `if_match`, `provenance`, `actor` |
| `kiwi_append` | Append to a page atomically, with no read-modify-write race. | `path`*, `content`*, `separator` |

| `kiwi_delete` | Delete a page. History stays in git. | `path`* |
| `kiwi_rename` | Move one page and respell every link to it. The destination must not exist. | `from`*, `to`*, `update_links` (default `true`) |
| `kiwi_tree` | List files and folders with sizes. | `path`, `depth`, `include_permalinks` |
