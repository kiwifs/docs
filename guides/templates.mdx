`kiwifs init` creates a knowledge directory from a built-in template. Pick the template closest to how you will use the knowledge base. Everything it creates is plain markdown plus a `.kiwi/` folder, so you can change any of it later.

```bash Terminal
kiwifs init --template wiki --root ./knowledge
kiwifs serve --root ./knowledge
```

| Flag | Default | Description |
| --- | --- | --- |
| `--template` | `kb` | Template name (see below) |
| `--root`, `-r` | `./knowledge` | Directory to initialize |

`init` never overwrites existing files, so it is safe to run on a folder that already has content.

## Available templates

| Template | Best for | What you get |
| --- | --- | --- |
| `kb` | Curated knowledge bases | Article types, verification workflow, freshness checks |
| `wiki` | Team wikis | Onboarding, decision records, processes, reference docs |
| `memory` | Agent memory | Episodic and semantic pages, consolidation log |
| `tasks` | Task tracking | Task schema, status workflow with WIP limits, claim fields |
| `data` | Structured records | Collections, DQL dashboards, chart widgets |
| `cms` | Headless CMS | Blog, docs, pages, authors, editorial workflow, feeds |
| `runbook` | Ops and incident response | Severity and service frontmatter, execution staleness |
| `adr` | Architecture decision records | MADR format, status workflow, auto-numbering |
| `prompt` | Prompt registry | System and task prompts, eval rubrics |
| `research` | Literature and papers | Paper tracking, reading workflow, typed citation links |
| `log` | Append-only event logs | Daily files that reject overwrites |
| `blank` | Starting from scratch | Config, rules, and page templates only |

<Note>
The old template names `knowledge` and `prompt-library` are now `memory` and `prompt`. Using an old name returns an error that names the new one.
</Note>

## What every template includes

Every template, including `blank`, creates:

- `.kiwi/config.toml` — server, search, versioning, and auth settings. Some templates ship their own; the rest get the default config.
- `.kiwi/rules.md` — agent rules you can export with `kiwifs rules export`.
- `.kiwi/templates/` — page templates for decisions, meeting notes, onboarding, product specs, SOPs, and tasks.
- `.gitignore` — ignores `.kiwi/state/`, which holds rebuildable indexes.
- `README.md`

Every template except `blank` also includes two documents for agents:

- **`SCHEMA.md`** — folder layout, frontmatter fields, and naming conventions.
- **`playbook.md`** — step-by-step MCP tool sequences for common operations. `init` writes it to both the root and `.kiwi/playbook.md`. Agents receive it through `kiwi_context`.

See [Agent playbook](/concepts/agent-playbook).

### Export agent rules

Turn `.kiwi/rules.md` into the rules file your agent harness reads:

```bash Terminal
kiwifs rules export --format cursor    # default
kiwifs rules export --format claude
kiwifs rules export --format agents
kiwifs rules export --format skill
kiwifs rules export --format openclaw
```

  <Accordion title="tasks — task tracking" icon="list-check">
    Tasks as markdown files, ready for the kanban board and [claims](/concepts/claims). Uses the default config.

    <Tree>
      <Tree.Folder name="knowledge" defaultOpen>
        <Tree.File name="SCHEMA.md" />
        <Tree.File name="WORKFLOW.md" />
        <Tree.File name="playbook.md" />
        <Tree.File name="index.md" />
        <Tree.Folder name="tasks" />
        <Tree.Folder name=".kiwi" defaultOpen>
          <Tree.File name="schemas/task.json" />
          <Tree.File name="workflows/tasks.json" />
        </Tree.Folder>
      </Tree.Folder>
    </Tree>

    - **Task frontmatter:** `type: task`, `title`, `status`, and `priority` (an integer) are required. Optional fields include `category`, `effort`, `assignee`, `parent`, `blocked-by`, `due`, and claim fields such as `claimed-by` and `lease-expires`. Workflow actions read `workflow` and `state`, which is what the shipped example pages use.
    - **Workflow:** `backlog → todo → in_progress → review → done`, with `cancelled` reachable from every open state. `in_progress` has a WIP limit of 5 and `review` a limit of 3.

    ```yaml tasks/example-task.md
    ---
    type: task
    title: Implement auth flow
    workflow: tasks
    state: in_progress
    priority: 1
    assignee: agent:eng-bot
    blocked_by: []
    ---
    ```

    Advance a task through the workflow:

    ```bash Terminal
    curl -X POST 'http://localhost:3333/api/kiwi/workflow/advance' \
      -H 'Content-Type: application/json' \
      -d '{"path":"tasks/example-task.md","target_state":"review","actor":"agent:bot"}'
    ```
  </Accordion>

## List templates over HTTP

A running server lists its templates at `/api/init-templates`, outside the `/api/kiwi` prefix:

```bash Terminal
curl http://localhost:3333/api/init-templates
```

```json Response
{
  "templates": [
    {
      "id": "adr",
      "label": "Architecture Decision Records",
      "description": "Architecture Decision Records with MADR format, status workflow, and JSON Schema"
    },
    {
      "id": "blank",
      "label": "Blank",
      "description": "Empty workspace with Kiwi config only"
    }
  ]
}
```

Templates are sorted by label, with `blank` last.
