This takes about five minutes. You need macOS or Linux (amd64 or arm64), or Docker.

<Steps>
  <Step title="Install KiwiFS">
    <Tabs>
      <Tab title="Release binary">
        Download the latest release for your platform and put it on your `PATH`:

        ```bash Terminal
        OS=$(uname -s | tr '[:upper:]' '[:lower:]')
        ARCH=$(uname -m | sed -e 's/x86_64/amd64/' -e 's/aarch64/arm64/')
        curl -fsSL "https://github.com/kiwifs/kiwifs/releases/latest/download/kiwifs-$OS-$ARCH.tar.gz" | tar -xz
        sudo mv "kiwifs-$OS-$ARCH" /usr/local/bin/kiwifs
        kiwifs --version
        ```

        All builds are on the [releases page](https://github.com/kiwifs/kiwifs/releases), each with a `.sha256` checksum.
      </Tab>
      <Tab title="Docker">
        ```bash Terminal
        docker run -d --name kiwifs -p 3333:3333 -v kiwifs-data:/data ameliaanhlam/kiwifs
        ```

        The container runs `kiwifs serve --root /data` and creates a knowledge base from the `kb` template on first start. Skip to step 4.

        To keep the files in a host folder instead of a named volume, see [Docker](/deploy/docker).
      </Tab>
      <Tab title="From source">
        Requires Go 1.27+, Node 20+, and `make`. The build compiles the web UI and embeds it in the binary.

        ```bash Terminal
        git clone https://github.com/kiwifs/kiwifs.git
        cd kiwifs
        make build
        ./kiwifs --version
        ```

        <Warning>
        `go install github.com/kiwifs/kiwifs@latest` does not work: the module does not include the built web UI, so the embed step fails. Use `make build`.
        </Warning>
      </Tab>
    </Tabs>
  </Step>

  <Step title="Create a knowledge base">
    ```bash Terminal
    kiwifs init --root ./knowledge
    ```

    This scaffolds the default `kb` template: sample pages, page schemas, a workflow, and a `.kiwi/` folder with configuration and an agent playbook.

    <Tree>
      <Tree.Folder name="knowledge" defaultOpen>
        <Tree.Folder name=".kiwi" defaultOpen>
          <Tree.File name="config.toml" />
          <Tree.File name="playbook.md" />
          <Tree.File name="rules.md" />
          <Tree.Folder name="schemas" />
          <Tree.Folder name="templates" />
          <Tree.Folder name="workflows" />
        </Tree.Folder>
        <Tree.Folder name="getting-started" />
        <Tree.Folder name="guides" />
        <Tree.Folder name="reference" />
        <Tree.File name="index.md" />
        <Tree.File name="SCHEMA.md" />
      </Tree.Folder>
    </Tree>

    Pass `--template` to start from something else, such as `wiki`, `memory`, `tasks`, `adr`, or `blank`. See [Init templates](/guides/templates) for all twelve.
  </Step>

  <Step title="Start the server">
    ```bash Terminal
    kiwifs serve --root ./knowledge
    ```

    Open [http://localhost:3333](http://localhost:3333) to see the web UI. The same port serves the REST API under `/api/kiwi/` and MCP over HTTP at `/mcp`.

    <Tip>
    You can skip `init`. If the root has no `.kiwi/config.toml`, `serve` initializes it with the `kb` template first.
    </Tip>
  </Step>

  <Step title="Write a page">
    Write through the API or straight to disk. Both go through the same pipeline.

    <CodeGroup>
    ```bash REST
    curl -X PUT 'http://localhost:3333/api/kiwi/file?path=notes/auth.md' \
      -H 'X-Actor: my-agent' \
      --data-binary $'# Authentication\n\nOAuth2 with JWT access tokens.\n'
    ```

    ```bash Filesystem
    mkdir -p knowledge/notes
    printf '# Authentication\n\nOAuth2 with JWT access tokens.\n' > knowledge/notes/auth.md
    ```
    </CodeGroup>

    The REST call returns the new ETag, which you pass as `If-Match` on later writes to detect conflicts:

    ```json
    {"etag":"934818f7f7cc3f1a23edc793a08bc8720fc05085","path":"notes/auth.md"}
    ```
  </Step>

  <Step title="Verify it was indexed and versioned">
    ```bash Terminal
    curl 'http://localhost:3333/api/kiwi/search?q=jwt'
    curl 'http://localhost:3333/api/kiwi/versions?path=notes/auth.md'
    ```

    The search returns `notes/auth.md` with the match highlighted. The versions list shows one commit whose author is `my-agent`, or `fswatch` if you wrote to disk.

    <Check>
    Your knowledge base is running. Every write is now searchable within a moment and recorded as a git commit.
    </Check>
  </Step>
</Steps>

## Connect an agent

Point an MCP client at the running server. Your agent gets 78 tools for reading, writing, searching, querying, refactoring, and coordinating through drafts and claims.

<Tabs>
  <Tab title="Claude Code">
    ```bash Terminal
    claude mcp add --transport http kiwifs http://localhost:3333/mcp
    ```
  </Tab>
  <Tab title="Claude Desktop and Cursor">
    ```json MCP config
    {
      "mcpServers": {
        "kiwifs": {
          "command": "kiwifs",
          "args": ["mcp", "--remote", "http://localhost:3333"]
        }
      }
    }
    ```
  </Tab>
  <Tab title="No server">
    Without a running server, `kiwifs mcp` can open the folder directly:

    ```json MCP config
    {
      "mcpServers": {
        "kiwifs": {
          "command": "kiwifs",
          "args": ["mcp", "--root", "/absolute/path/to/knowledge"]
        }
      }
    }
    ```

    Use `--remote` instead whenever `kiwifs serve` is running on the same folder, so that one process owns the writes.
  </Tab>
</Tabs>

See [MCP](/concepts/mcp) for the tool reference and remote auth.
