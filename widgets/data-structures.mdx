These fences draw a data structure from YAML and step through changes to it. Use them to explain an algorithm, a database internal, or a runtime behavior, with each step's reasoning in a `note`.

Every fence here follows the shared rules for [steps, meta strings, playback, and validation](/concepts/widgets#writing-a-typed-fence). Each key table lists the exact keys the linter accepts.

## array

One or more arrays on a shared index axis, with pointers, dependency arrows, and span brackets. Use `rows:` to stack several arrays, such as `nums` over `dp`, on one index axis.

A bare `array` fence renders when its body has `values` or `rows`. Also spelled `kiwi-array`, `widget:array`, `arraystack`, `kiwi-arraystack`.

````markdown
```array id=two-sum caption="Two-pointer sweep on a sorted array"
values: [2, 7, 11, 15, 19]
pointers:
  - {index: 0, label: lo}
  - {index: 4, label: hi}
steps:
  - note: "2 + 19 = 21 > 9 — move hi left"
    activeIndices: [0, 4]
    line: 3
  - note: "2 + 15 = 17 > 9 — move hi left"
    pointers: [{index: 0, label: lo}, {index: 3, label: hi}]
    activeIndices: [0, 3]
  - note: "2 + 7 = 9 — found it"
    pointers: [{index: 0, label: lo}, {index: 1, label: hi}]
    activeIndices: [0, 1]
    breakpoint: true
code: |
  lo, hi = 0, len(a) - 1
  while lo < hi:
      s = a[lo] + a[hi]
      if s == target: return lo, hi
      if s > target: hi -= 1
      else: lo += 1
lang: python
```
````

## matrix

An index-addressed grid: DP tables, game boards, adjacency and confusion matrices. Address cells as `[r, c]` or `"r,c"`. Set `heatmap: true` to shade numeric cells, or `layers:` to show slices of a 3-D table as tabs.

A bare `matrix` fence renders when its body has `values` or `layers`. Also spelled `kiwi-matrix`, `widget:matrix`, `grid`, `kiwi-grid`, `dp`.

````markdown
```matrix id=lcs caption="Longest common subsequence of ABC and AC"
rowHeaders: ["", A, B, C]
colHeaders: ["", A, C]
values:
  - [0, 0, 0]
  - [0, 1, 1]
  - [0, 1, 1]
  - [0, 1, 2]
steps:
  - note: "Characters match: take the diagonal and add one"
    activeCells: [[1, 1]]
    readCells: [[0, 0]]
    line: 4
  - note: "No match: carry the better of above and left"
    activeCells: [[2, 2]]
    readCells: [[1, 2], [2, 1]]
    line: 6
  - note: "Match again — the answer is 2"
    activeCells: [[3, 2]]
    readCells: [[2, 1]]
    path: [[3, 2], [2, 1], [1, 1]]
code: |
  for i in range(1, n + 1):
      for j in range(1, m + 1):
          if a[i-1] == b[j-1]:
              dp[i][j] = dp[i-1][j-1] + 1
          else:
              dp[i][j] = max(dp[i-1][j], dp[i][j-1])
lang: python
```
````

## table

A named-column table: relations, schemas, lock tables, MVCC row versions, decision tables. Address cells as `"rowKey.colKey"`. Set `fromData: <kind>` to render the records of a [`kiwi-data`](/widgets/data-and-queries#kiwi-data) block on the same page, so the dataset and the walkthrough that animates it share one source.

The `why` map below lets a reader click a cell and read why it says what it says.

A bare `table` fence renders when its body has `columns` or `rows` or `fromData`. Also spelled `kiwi-table`, `widget:table`, `relation`.

````markdown
```table id=sev caption="Severity ladder"
columns:
  - {key: sev, label: Sev, pk: true}
  - {key: response, label: Response}
  - {key: ack, label: Ack target, align: right}
rows:
  - {sev: SEV1, response: Page IM + exec bridge, ack: 5m}
  - {sev: SEV2, response: Page on-call + team lead, ack: 15m}
  - {sev: SEV3, response: "Slack #platform-oncall", ack: 1h}
why:
  SEV2.response: >
    Team lead, not the exec bridge: a SEV2 that pulls in leadership stops
    being a SEV2 and starts being a meeting.
```
````

## tree

Binary, n-ary, and keyed trees. Nest nodes under `root:`, or use one of the shortcuts: `fromArray` builds a heap (and draws its backing array beside it), `parents` builds a union-find forest, and `keys` on a node turns it into a B-tree page.

A bare `tree` fence renders when its body has `root` or `roots` or `parents` or `fromArray`. Also spelled `kiwi-tree`, `widget:tree`.

````markdown
```tree id=heap caption="Sift-down after popping the root"
fromArray: [1, 3, 2, 7, 5, 9]
steps:
  - note: "Pop the root; move the last element up"
    activeNodes: [0]
  - note: "9 is bigger than both children — swap with the smaller, 2"
    activeNodes: [0, 2]
    highlightNodes: [1]
  - note: "Heap property restored"
    dimNodes: [0, 1, 2]
```
````

## list

A linked list. Each node's `next` defaults to the following node. `next: false` ends the list, and a number points back to that index, which is how you draw a cycle.

A bare `list` fence renders when its body has `nodes`. Also spelled `kiwi-list`, `widget:list`, `linkedlist`, `linked-list`, `kiwi-linkedlist`.

````markdown
```list id=floyd caption="Floyd's cycle detection"
nodes:
  - {value: 1}
  - {value: 2}
  - {value: 3}
  - {value: 4}
  - {value: 5, next: 2}
steps:
  - note: "slow and fast both start at the head"
    pointers: [{index: 0, label: slow}, {index: 0, label: fast}]
  - note: "slow moves one, fast moves two"
    pointers: [{index: 1, label: slow}, {index: 2, label: fast}]
  - note: "fast has entered the cycle"
    pointers: [{index: 2, label: slow}, {index: 4, label: fast}]
  - note: "They meet inside the cycle — there is one"
    pointers: [{index: 3, label: "slow,fast"}]
    activeIndex: 3
    breakpoint: true
```
````

| `entries` | array or object | `[{key, value?}]` for `mode: "map"` — a frequency map, a seen-set. A plain `{key: value}` object works too. |
| `hashOf` | object | Key → slot, shown as an `h(k)=i` badge beside the key in every mode. |
| `highlightColor` | string | Secondary highlight color. Fixed across steps. |
| `highlightSlots` | array or number or string | Secondary-highlighted slots. |
| `mode` | `chain` \| `open` \| `map` | How to draw it: "chain" for buckets, "open" for open addressing with tombstones, "map" for an unordered dictionary. Inferred from `slots` / `entries`. Fixed across steps. |
| `probePath` | array of number | Slots visited in order, numbered above the row and joined by arrows. |
| `props` | any | Escape hatch for a widget prop whose name collides with a reserved key. |
| `selected` | array or number or string | Slot indices drawn as selected; keys in `mode: "map"`. |
| `showIndices` | boolean | Index captions under the slots. Default true. Fixed across steps. |
| `showLoadFactor` | boolean | Show α = n/m: entries per slot for chaining, occupied slots for open addressing. Default true. Fixed across steps. |
| `slots` | array | One entry per slot: `null` empty, `"DEL"` a tombstone, `{key, value?}` or a bare key, or a list of those for a chain. |
| `slotWidth` | number | Slot width, px. Default 54. Fixed across steps. |
| `tombstones` | array or number or string | Slots holding a tombstone, if not already `"DEL"`. |
| `why` | any | Slot index (key in `mode: "map"`) → explanation, revealed on select. |
| `widgetId` | string | Name for the inspect bus, for cross-widget linking. Fixed across steps. |

</Accordion>

## bits

A value as labelled bits: bitmask DP, flag registers, permission sets, two's complement, IEEE-754 layouts. `fields` brackets named bit ranges, and `decode` chooses how the summary row reads the pattern.

A bare `bits` fence renders when its body has `value`. Also spelled `kiwi-bits`, `widget:bits`, `bitmask`.

````markdown
```bits id=subsets caption="Bitmask DP: visiting city 2"
bits: 4
labels: [A, B, C, D]
steps:
  - note: "Start at A only"
    value: 1
    activeBits: [0]
  - note: "Add C to the visited set"
    value: 5
    activeBits: [2]
    readBits: [0]
  - note: "All four visited — the subproblem is complete"
    value: 15
    activeBits: [1, 3]
```
````

| Key | Type | Description |
| --- | --- | --- |
| `value` | number or string | **Required.** The value to show. A number, or a `"0x…"` / `"0b…"` string for 64-bit patterns a JS number cannot hold exactly. |
| `activeBits` | array or number or string | Bit positions being set or tested this step. |
| `activeColor` | string | Primary highlight color. Fixed across steps. |
| `ariaLabel` | string | Accessible name. Defaults to a summary derived from the data. Fixed across steps. |
| `arrows` | array of object | Arcs between bit positions: `{from, to, label?, dashed?}`. |
| `bits` | number | How many bits to draw. Defaults to the value's bit length. Fixed across steps. |
| `cellSize` | number | Cell size, px. Fixed across steps. |
| `decode` | `uint` \| `int` \| `twos` \| `ieee32` \| `ieee64` \| `hex` \| `oct` \| `raw` | How to read the pattern in the summary row. A list shows several readings at once. Default uint. |
| `fields` | array of object | Named bit ranges drawn as brackets under the row: `{from, to, label, color?}` — a float's sign, exponent and mantissa; a flags register; a packed struct. Each bracket shows the field's value. |
| `highlightBits` | array or number or string | Secondary-highlighted bit positions. |
| `highlightColor` | string | Secondary highlight color. Fixed across steps. |
| `label` | string | Row title, e.g. `mask`. |
| `labels` | array | What each bit stands for, indexed by bit position (bit 0 = least significant). |
| `lsbFirst` | boolean | Draw bit 0 on the left. Default false (most significant first). Fixed across steps. |
| `pointers` | array of object | Pointers by bit position: `{bit, label, color?, side?}`. |

## memory

Frames on the left, heap objects on the right, pointers between them: aliasing, mutation, closures, recursion. The props follow the Python Tutor trace format, so a recorded trace drops straight in. A frame variable written as `[REF, id]` points into the heap.

A bare `memory` fence renders when its body has `frames` or `heap`. Also spelled `kiwi-memory`, `widget:memory`, `heap`, `stack-heap`.

````markdown
```memory id=alias caption="Why mutating b changed a"
frames:
  - name: "<module>"
    vars: {a: [REF, 1], b: [REF, 1]}
heap:
  1: [LIST, 1, 2, 3]
steps:
  - note: "a = [1, 2, 3] allocates one list"
    frames:
      - {name: "<module>", vars: {a: [REF, 1]}}
    activeIds: [1]
  - note: "b = a copies the pointer, not the list — both names are the one object"
    frames:
      - {name: "<module>", vars: {a: [REF, 1], b: [REF, 1]}}
    activeIds: [1]
  - note: "b.append(4) mutates that object, so a sees it too"
    heap:
      1: [LIST, 1, 2, 3, 4]
    activeIds: [1]
    breakpoint: true
```
````

| Key | Type | Description |

| `activeFrame` | string or number | Which frame is executing: a frame `id`, or a number for its index in `frames`. Defaults to the innermost. |
| `activeIds` | array or number or string | Heap ids to emphasise this step. |

| `dimIds` | array or number or string | Dimmed heap ids — garbage, or a frame about to return. |

| `heap` | object | Objects by id, tagged: `["LIST", 1, 2]`, `["DICT", ["k", 1]]`, `["INSTANCE", "Node", ["val", 1]]`, `["TUPLE", …]`, `["SET", …]`. An untagged `{field: value}` draws as an object's fields. |
| `heapLabel` | string | Caption above the heap column. Default "Objects". Fixed across steps. |
| `highlightColor` | string | Secondary highlight color. Fixed across steps. |
| `highlightIds` | array or number or string | Secondary-highlighted heap ids. |
