These endpoints support agents and the web UI around the core file API: reading a page in pieces, linting and rendering, following activity, storing per-user settings, and running admin checks. They use the `/api/kiwi` prefix and the authentication rules in the [API overview](/api/overview), except `/raw/*` and `/llms.txt`, which have their own rules described below.

Symlink targets (`GET /api/kiwi/readlink`) and page templates (`GET /api/kiwi/templates`, `GET /api/kiwi/template`) are documented with the [Files API](/api/files).

## Content helpers

### Lint markdown

Check a page, or markdown you haven't saved yet, for structural problems the editor can't fix automatically.

```http
POST /api/kiwi/lint
```

<ParamField body="path" type="string">
  File to lint. Ignored when `content` is set.
</ParamField>
<ParamField body="content" type="string">
  Markdown to lint inline.
</ParamField>

```bash
curl -X POST 'http://localhost:3333/api/kiwi/lint' \
  -H "Content-Type: application/json" \
  -d '{"path": "concepts/auth.md"}'
```

Returns `400` when neither `path` nor `content` is set and `404` when `path` does not exist.

<ResponseField name="issues" type="object[]">
  Problems found. Always an array, empty when the page is clean.
  <Expandable title="properties">
    <ResponseField name="rule" type="string">Rule ID, such as `frontmatter-yaml-invalid`, `table-column-mismatch`, `fence-unclosed`, `fence-mermaid-invalid`, `fence-widget-invalid`, `quiz-invalid`, `heading-skip-level`, or `link-image-broken`.</ResponseField>
    <ResponseField name="line" type="integer">1-based line. `0` means the whole file.</ResponseField>
    <ResponseField name="column" type="integer">1-based column. `0` means not applicable.</ResponseField>
    <ResponseField name="message" type="string">Human-readable description.</ResponseField>
    <ResponseField name="severity" type="string">`error`, `warning`, or `info`.</ResponseField>
  </Expandable>
</ResponseField>

```json
{
  "issues": [
    { "rule": "heading-skip-level", "line": 12, "column": 0, "message": "heading jumps from h2 to h4", "severity": "warning" }
  ]
}
```

<ParamField query="path" type="string" required>

</ParamField>


<ResponseField name="title" type="string">First heading, or the file name.</ResponseField>
<ResponseField name="frontmatter" type="object">Parsed frontmatter.</ResponseField>
<ResponseField name="snippet" type="string">First paragraph, up to 300 characters.</ResponseField>
<ResponseField name="links_out" type="string[]">Wiki link targets in the page, as written.</ResponseField>
<ResponseField name="links_in" type="string[]">Pages that link to this one.</ResponseField>
<ResponseField name="word_count" type="integer">Words in the body.</ResponseField>
<ResponseField name="headings" type="string[]">Heading text, in order.</ResponseField>


### Ingest a document

Convert a document on the server's filesystem (PDF, Office, HTML, images, audio, and more) to markdown and write it into the knowledge base. Requires the [`markitdown`](https://github.com/microsoft/markitdown) CLI on the server's `PATH`.

```http
POST /api/kiwi/ingest
```

<ParamField body="file" type="string" required>
  Path to the source file on the server. Supported extensions: `pdf`, `docx`, `pptx`, `xlsx`, `html`, `htm`, `csv`, `json`, `xml`, `epub`, `jpg`, `jpeg`, `png`, `gif`, `bmp`, `tiff`, `mp3`, `wav`, `m4a`, `zip`.
</ParamField>
<ParamField body="split_mode" type="string" default="single">
  `single` writes one page. `sections` writes one page per heading.
</ParamField>
<ParamField body="prefix" type="string" default="imports/<file-name>/">
  Folder for the output pages.
</ParamField>
<ParamField body="extract_keywords" type="boolean" default="false">
  Add TF-IDF keywords to each page.
</ParamField>
<ParamField body="max_keywords" type="integer" default="10">
  Keywords per section when `extract_keywords` is on.
</ParamField>
<ParamField body="convert_crossrefs" type="boolean" default="false">
  Turn references between sections into wiki links.
</ParamField>
<ParamField body="actor" type="string" default="kiwi-ingest">
  Git commit author attribution.
</ParamField>

```bash
curl -X POST 'http://localhost:3333/api/kiwi/ingest' \
  -H "Content-Type: application/json" \
  -d '{"file": "/data/inbox/q3-report.pdf", "split_mode": "sections", "extract_keywords": true}'
```

Returns `400` for a missing `file` or unsupported extension and `500` if conversion or writing fails (including when `markitdown` is not installed).

<ResponseField name="source_file" type="string">Source path.</ResponseField>
<ResponseField name="format" type="string">Source extension.</ResponseField>
<ResponseField name="total_sections" type="integer">Sections found in the converted document.</ResponseField>
<ResponseField name="output_files" type="string[]">Pages written.</ResponseField>
<ResponseField name="top_keywords" type="string[]">Extracted keywords, if enabled.</ResponseField>

```json
{
  "source_file": "/data/inbox/q3-report.pdf",
  "format": ".pdf",
  "total_sections": 3,
  "output_files": ["imports/q3-report/summary.md", "imports/q3-report/revenue.md", "imports/q3-report/outlook.md"],
  "top_keywords": ["revenue", "churn", "pipeline"]
}
```

### Rules file

Read or replace `.kiwi/rules.md`, the team's instructions for agents. `GET` can also wrap the rules in a ready-made file for a specific agent harness.

```http
GET /api/kiwi/rules
PUT /api/kiwi/rules
```

<ParamField query="format" type="string">
  `GET` only. One of `cursor`, `claude`, `agents`, `openclaw`, or `skill`. Omit it to get the raw file.
</ParamField>
<ParamField header="X-Actor" type="string">
  `PUT` only. Git commit author attribution.
</ParamField>

<CodeGroup>
```bash Read raw rules
curl 'http://localhost:3333/api/kiwi/rules'
```

```bash Read as a Cursor rules file
curl 'http://localhost:3333/api/kiwi/rules?format=cursor'
```

```bash Replace rules
curl -X PUT 'http://localhost:3333/api/kiwi/rules' \
  -H "Content-Type: text/markdown" \
  --data-binary @rules.md
```
</CodeGroup>

`GET` returns plain text, or an empty body when the file doesn't exist. `PUT` takes raw markdown up to 256 KB, returns `413` above that, and commits the file.

```json PUT response
{ "status": "ok", "path": ".kiwi/rules.md" }
```

## Real-time events

### Subscribe to events

Open a [Server-Sent Events](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events) stream that receives an event for every change. See [Real-time events](/concepts/real-time-events) for client patterns.

```http
GET /api/kiwi/events
```

```bash
curl -N 'http://localhost:3333/api/kiwi/events'
```

Each message has an `event:` line with the event type and a `data:` line with a JSON object. The server sends a `:keep-alive` comment every 15 seconds. It returns `503` when 256 clients are already connected. Events are not replayed, so reconnect and re-read state after a disconnect.

```text
event: write
data: {"op":"write","path":"concepts/auth.md","actor":"agent:docs-writer","etag":"a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2"}

event: delete
data: {"op":"delete","path":"concepts/old-page.md","actor":"agent:cleanup"}

event: bulk
data: {"op":"bulk","paths":["a.md","b.md"],"actor":"agent:importer"}
```

<ResponseField name="op" type="string">Event type. Same as the `event:` line.</ResponseField>
<ResponseField name="path" type="string">File path, for single-file events.</ResponseField>
<ResponseField name="paths" type="string[]">File paths, for `bulk` and `rollback`.</ResponseField>
<ResponseField name="actor" type="string">Who made the change.</ResponseField>
<ResponseField name="etag" type="string">New git blob hash, on most `write` events.</ResponseField>
<ResponseField name="extra" type="object">Event-specific details, such as the janitor scan summary.</ResponseField>

| Event | Sent when |
| --- | --- |
| `write` | A file is created or updated, including the new path of a rename |
| `delete` | A file is deleted, including the old path of a rename |
| `bulk` | A bulk write commits |
| `rollback` | A bulk write fails and its files are restored |
| `comment.add` | A comment is added |
| `comment.resolve` | A comment is resolved or reopened |
| `comment.delete` | A comment is deleted |
| `janitor` | A scheduled janitor scan finishes or fails |

## Comments

Comments are inline annotations anchored to a quoted span of a page. They are stored in `.kiwi/comments/<path>.json`, and every change is committed to git and broadcast as an SSE event.

Return every comment on a page, resolved or not.

```http

```

<ParamField query="path" type="string" required>
  Page path.
</ParamField>

```bash
curl 'http://localhost:3333/api/kiwi/comments?path=concepts/auth.md'
```

<ResponseField name="path" type="string">Page path.</ResponseField>

### Add a comment

Attach a comment to a span of text in a page.

```http
POST /api/kiwi/comments
```

</ParamField>

<ParamField body="anchor" type="object" required>
  <Expandable title="properties">

    <ParamField body="suffix" type="string">Text just after the quote.</ParamField>

## Rendering

### Render a D2 diagram

Render [D2](https://d2lang.com) source to SVG on the server. The web UI uses this for ` ```d2 ` fences. Use `GET` for short sources and `POST` when the source is too long for a URL.

```http
GET /api/kiwi/render/d2
POST /api/kiwi/render/d2
```

<ParamField query="source" type="string">
  `GET` only. D2 source.
</ParamField>
<ParamField query="theme" type="string" default="light">
  `GET` only. `light` or `dark`.
</ParamField>
<ParamField body="source" type="string" required>
  `POST` only. D2 source, up to 64 KB.
</ParamField>
<ParamField body="theme" type="string" default="light">
  `POST` only. `light` or `dark`.
</ParamField>

```bash
curl -X POST 'http://localhost:3333/api/kiwi/render/d2' \
  -H "Content-Type: application/json" \
  -d '{"source": "api -> db: query\napi -> cache", "theme": "dark"}' \
  -o diagram.svg
```

Returns an `image/svg+xml` body with an `ETag`. Send that ETag back in `If-None-Match` to get `304`. Layout uses dagre by default; set `layout-engine: elk` in the source's `d2-config` to use ELK. Imports are disabled. Error codes:

- `400`: empty source or source over 64 KB
- `422`: the diagram has a syntax or layout error (the message says where)
- `501`: the server was built without D2 support
- `503`: rendering took longer than 10 seconds

## Raw files and llms.txt

### Raw files

Serve a file's bytes directly, for `<img>`, `<video>`, and `<iframe>` tags and downloads. Use [`GET /file`](/api/files#read-a-file) instead when you need an `ETag`.

```http
GET /raw/:path
GET /api/kiwi/raw/:path
```

<ParamField path="path" type="string" required>
  File path relative to the knowledge root.
</ParamField>
<ParamField query="exp" type="string">
  Expiry from a [signed URL](#sign-a-raw-url).
</ParamField>
<ParamField query="sig" type="string">
  Signature from a signed URL.
</ParamField>

```bash
curl -O 'http://localhost:3333/raw/assets/diagram.png' \
  -H "Authorization: Bearer $KIWI_API_KEY"
```

The `/api/kiwi/raw/` alias lets the web UI reach assets in a non-primary space. When auth is on and the space is `private`, a request must have one of:

- an `Authorization` header
- a valid `exp` and `sig` pair (otherwise `403`)
- a target that is already public: a branding logo or favicon, a page with `published: true` or `visibility: public`, or an asset next to such a page

Spaces with `public` or `unlisted` visibility serve raw files without credentials. Returns `404` if the file does not exist. SVGs are served with a restrictive `Content-Security-Policy`.

### Sign a raw URL

Get a short-lived `/raw/` URL that works without an `Authorization` header, for embedding private assets in HTML.

```http
GET /api/kiwi/raw-sign
```

<ParamField query="path" type="string" required>
  File path.
</ParamField>

```bash
curl 'http://localhost:3333/api/kiwi/raw-sign?path=assets/diagram.png' \
  -H "Authorization: Bearer $KIWI_API_KEY"
```

Returns `400` if `path` is missing or escapes the knowledge root. URLs stay valid for 30 to 60 minutes and stop working when the server restarts.

<ResponseField name="path" type="string">Normalized file path.</ResponseField>
<ResponseField name="url" type="string">Signed relative URL.</ResponseField>
<ResponseField name="expires" type="string">Expiry time (RFC 3339, UTC).</ResponseField>

```json
{
  "path": "assets/diagram.png",
  "url": "/raw/assets/diagram.png?exp=1792418400&sig=Zk3x...",
  "expires": "2026-10-19T15:00:00Z"
}
```

### llms.txt

Describe the knowledge base in the [llms.txt](https://llmstxt.org) format, for agents that don't use MCP. These routes sit at the server root, not under `/api/kiwi`.

```http
GET /llms.txt
GET /llms-full.txt
```

```bash
curl 'http://localhost:3333/llms.txt'
```

`/llms.txt` returns a plain-text index: a title, a summary, and every page grouped by top-level folder, with its `description` frontmatter. `/llms-full.txt` returns the full markdown of every page, concatenated, with frontmatter stripped. It stops at 5 MiB and ends with a note saying how many pages were left out.

<Note>
These routes don't take credentials. When auth is on and the space isn't `public`, they list only pages with `published: true` or `visibility: public`, the same pages `/p/*` would serve.
</Note>

```http

```

<ParamField header="X-Actor" type="string">

<CodeGroup>
```bash Read
curl 'http://localhost:3333/api/kiwi/theme'
```


### User preferences

Read or update the calling user's web UI preferences, stored in `.kiwi/users/<user-id>/preferences.json`. The user comes from `X-Actor`, which the auth layer sets from your credentials.

```http
GET /api/kiwi/preferences
PUT /api/kiwi/preferences
```

<ParamField body="theme" type="string">Color theme.</ParamField>
<ParamField body="sidebar_collapsed" type="boolean">Whether the sidebar starts collapsed.</ParamField>
<ParamField body="default_view" type="string">`editor` or `source`.</ParamField>
<ParamField body="font_size" type="string">`sm`, `base`, or `lg`.</ParamField>
<ParamField body="editor_line_numbers" type="boolean">Show line numbers in the source editor.</ParamField>
<ParamField body="vim_mode" type="boolean">Enable Vim keybindings in the source editor.</ParamField>

```bash
curl -X PUT 'http://localhost:3333/api/kiwi/preferences' \
  -H "Authorization: Bearer $KIWI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"font_size": "lg", "vim_mode": true}'
```

`PUT` merges the fields you send into the stored preferences, commits the file, and returns the merged result. Both methods return `401` for anonymous callers and the built-in web UI actor. `PUT` returns `400` for an invalid `default_view` or `font_size` and `413` above 8 KB.

```json
{ "theme": "dark", "font_size": "lg", "vim_mode": true }
```

### Personal state and notes

Store small JSON blobs per user, such as UI state, and read a user's private companion note for a page. Files live in `.kiwi/users/<user-id>/state/` for authenticated users and in `.me/` otherwise. These files are written directly and are not committed to git.

```http
GET /api/kiwi/me/state
PUT /api/kiwi/me/state
GET /api/kiwi/me/note
```

<ParamField query="name" type="string">
  `me/state` only, required. State name. Must not contain `/`, `\`, or `.`.
</ParamField>
<ParamField query="path" type="string">
  `me/note` only, required. Page path. The note is the file with the same base name in the user's state folder.
</ParamField>

<CodeGroup>
```bash Save state
curl -X PUT 'http://localhost:3333/api/kiwi/me/state?name=reading-list' \
  -H "Content-Type: application/json" \
  -d '{"pages": ["concepts/auth.md"]}'
```

```bash Read state
curl 'http://localhost:3333/api/kiwi/me/state?name=reading-list'
```

```bash Read a note
curl 'http://localhost:3333/api/kiwi/me/note?path=concepts/auth.md'
```
</CodeGroup>

`GET /me/state` returns the stored JSON, or `{}` when nothing is stored. `PUT /me/state` takes any valid JSON up to 512 KB and returns `204`. It returns `400` for a bad `name` or invalid JSON and `413` above 512 KB. `GET /me/note` returns `text/markdown`, or `404` when there is no note.
