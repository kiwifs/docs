Everything ships in one `kiwifs` binary. Run `kiwifs --help` to list commands, `kiwifs <command> --help` for details, and `kiwifs --version` to print the version.

Most commands that work on a knowledge base take `--root` (`-r`), which defaults to `./knowledge`.

## Server and agents

### serve

Start the HTTP server: REST API, web UI, and Streamable HTTP MCP at `/mcp`. Optional protocol servers (NFS, S3, WebDAV) run alongside.

<CodeGroup>
```bash Basic
kiwifs serve --root ./my-docs --port 8080
```

```bash With auth
kiwifs serve --auth apikey --api-key my-secret-key
```

```bash With NFS and S3
kiwifs serve --nfs --nfs-allow 10.0.0.0/8 --s3
```

```bash Multi-space
kiwifs serve --space team=./team-docs --space personal=./my-notes
```
</CodeGroup>

<AccordionGroup>
<Accordion title="Core flags">
| Flag | Default | Description |
| --- | --- | --- |
| `--root`, `-r` | `./knowledge` | Knowledge root directory |
| `--port`, `-p` | `3333` | HTTP port |
| `--host` | `0.0.0.0` | Bind address |
| `--search` | `sqlite` | Search engine: `sqlite` or `grep` |
| `--versioning` | `git` | Versioning strategy: `git`, `cow`, or `none` |
| `--auth` | `none` | Auth type: `none`, `apikey`, `perspace`, or `oidc` |
| `--api-key` | | API key (required with `--auth apikey`) |
| `--oidc-issuer` | | OIDC issuer URL (required with `--auth oidc`) |
| `--oidc-client-id` | | OIDC client ID (required with `--auth oidc`) |
| `--async-commit` | `true` | Batch git commits asynchronously |
| `--batch-window` | `200` | Async commit batch window, in milliseconds |
| `--batch-max-size` | `50` | Max paths per async commit batch |
| `--no-watch` | `false` | Disable the watcher that picks up direct writes to `--root` |
| `--space` | | Register an additional space, `name=path` (repeatable). Enables routing at `/api/kiwi/{name}/...` |
</Accordion>
<Accordion title="Protocol flags">
| Flag | Default | Description |
| --- | --- | --- |
| `--nfs` | `false` | Enable the userspace NFSv3 server |
| `--nfs-port` | `2049` | NFS port |
| `--nfs-allow` | localhost only | Comma-separated CIDRs allowed to mount NFS |
| `--s3` | `false` | Enable the S3-compatible API |
| `--s3-port` | `3334` | S3 port |
| `--webdav` | `false` | Enable the WebDAV server |
| `--webdav-port` | `3335` | WebDAV port |
</Accordion>
</AccordionGroup>

### mcp

Start the MCP server. It opens a directory in-process (`--root`) or proxies to a running server (`--remote`), over stdio or Streamable HTTP.

<CodeGroup>
```bash In-process (stdio)
kiwifs mcp --root ~/knowledge
```

```bash Proxy
kiwifs mcp --remote https://kiwi.example.com --api-key $KIWI_API_KEY
```

```bash Streamable HTTP
kiwifs mcp --root ~/knowledge --http --port 8181
```
</CodeGroup>

<Accordion title="Flags">
| Flag | Default | Description |
| --- | --- | --- |
| `--root` | | Knowledge root (in-process mode) |
| `--remote` | | KiwiFS server URL (proxy mode) |
| `--api-key` | | API key for the remote server, sent as a bearer token |
| `--space` | `default` | Space to scope to (`--remote` only) |
| `--http` | `false` | Serve Streamable HTTP at `/mcp` instead of stdio |
| `--port` | `8181` | HTTP port (requires `--http`) |
</Accordion>

Exactly one of `--root` or `--remote` is required. `kiwifs serve` already exposes MCP at `/mcp`, so you only need `kiwifs mcp --http` for a standalone MCP server. See [MCP](/concepts/mcp) for client setup and the tool list.

### mount

Mount a remote KiwiFS server as a local filesystem with FUSE. Not available on Windows.

```bash Terminal
kiwifs mount ~/mnt/kiwi --remote https://kiwi.example.com --api-key my-key
```

<Accordion title="Flags">
| Flag | Default | Description |
| --- | --- | --- |
| `--remote` | | Remote KiwiFS server URL (required) |
| `--api-key` | `$KIWIFS_API_KEY` | API key, sent as `X-API-Key` |
| `--bearer` | `$KIWIFS_BEARER` | Bearer token for the `Authorization` header |
| `--basic-user` | | HTTP Basic username |
| `--basic-pass` | `$KIWIFS_BASIC_PASS` | HTTP Basic password |
| `--space` | | A non-default space to mount |
</Accordion>

<Note>
Install [macFUSE](https://osxfuse.github.io/) on macOS or `fuse3` on Linux first.
</Note>

### lsp

A language server on stdin and stdout. When your editor renames or moves markdown files, it answers with the link edits that keep every link pointing at them, computed by the same planner as `kiwifs refactor`. Point your editor's generic LSP client at it.

```bash Terminal
kiwifs lsp --root ./knowledge
```

<Accordion title="Flags">
| Flag | Default | Description |
| --- | --- | --- |
| `--root`, `-r` | the editor's workspace folder | Knowledge root |
</Accordion>

## Restructuring

### refactor

Move, merge, split, and edit pages from a manifest without breaking links. Each apply is one commit that you can revert. See [Restructuring](/concepts/refactor) for the manifest format.

| Subcommand | Description |
| --- | --- |
| `refactor plan MANIFEST` | Preview a restructuring. Writes nothing. Exits `1` if the plan has errors. |
| `refactor apply MANIFEST` | Show the plan, confirm, and apply it as one commit. |
| `refactor revert COMMIT` | Show what reverting a commit would change, confirm, and apply it as a new commit. Refuses if affected files changed since. Requires git versioning. |

```bash Terminal
kiwifs refactor plan reorg.yaml --verbose
kiwifs refactor plan reorg.yaml --diff
kiwifs refactor apply reorg.yaml --yes
kiwifs refactor revert 3f9c2ab
```

If a KiwiFS server is serving `--root`, `apply` and `revert` send the change to that server so its index and live readers stay consistent.

<AccordionGroup>
<Accordion title="Flags for plan, apply, and revert">
| Flag | Default | Description |
| --- | --- | --- |
| `--root`, `-r` | `./knowledge` | Knowledge root |
| `--json` | `false` | Print the plan as JSON |
| `--verbose`, `-v` | `false` | List every rewritten link |
| `--diff` | `false` | Print a unified diff for every written page |
</Accordion>
<Accordion title="Extra flags for apply and revert">
| Flag | Default | Description |
| --- | --- | --- |
| `--yes`, `-y` | `false` | Apply without asking |
| `--server` | `http://127.0.0.1:<port from config>` | Server to send the change to when one holds `--root` |
| `--api-key` | `$KIWI_API_KEY` | API key for that server |
| `--actor` | `cli:refactor` | Actor recorded in the commit |
</Accordion>
</AccordionGroup>

## Data

### import

Import records from databases, files, or services. Each record becomes a markdown page with frontmatter.

<CodeGroup>
```bash PostgreSQL
kiwifs import --from postgres --dsn "postgres://user:pass@localhost/mydb" \
  --table articles --id-column slug --prefix articles/
```

```bash CSV
kiwifs import --from csv --file data.csv --id-column name --prefix people/
```

```bash Obsidian vault
kiwifs import --from obsidian --path /path/to/vault
```

```bash Infer a schema
kiwifs import --from csv --file students.csv --infer-schema --save-schema
```
</CodeGroup>

| Category | `--from` values |
| --- | --- |
| Databases | `postgres`, `mysql`, `sqlite`, `mongodb`, `firestore`, `dynamodb`, `redis`, `elasticsearch` |
| Files | `markdown`, `csv`, `json`, `jsonl`, `yaml`, `excel`, `bibtex`, `croissant` |
| Services | `notion`, `airtable`, `gsheets`, `obsidian`, `confluence` |

<AccordionGroup>
<Accordion title="Common flags">
| Flag | Default | Description |
| --- | --- | --- |
| `--from` | | Source type (required) |
| `--root`, `-r` | `./knowledge` | Knowledge root |
| `--prefix` | table or collection name | Path prefix for imported pages |
| `--columns` | | Comma-separated columns to include |
| `--id-column` | auto-detect | Column used as the file name |
| `--limit` | `0` | Max rows (`0` = unlimited) |
| `--dry-run` | `false` | Show what would be imported without writing |
| `--infer-schema` | `false` | Infer a JSON Schema from a `csv`, `json`, or `jsonl` sample and print it |
| `--save-schema` | `false` | Save the inferred schema to `.kiwi/schemas/<name>.json` (with `--infer-schema`) |
</Accordion>
<Accordion title="Source-specific flags">
| Flag | Used by |
| --- | --- |
| `--dsn` | `postgres`, `mysql` connection string |
| `--uri` | `mongodb` connection URI |
| `--db` | `sqlite` database file |
| `--file` | `csv`, `json`, `jsonl`, `yaml`, `excel`, `bibtex`, `croissant` |
| `--path` | `markdown`, `obsidian`, `confluence` directory |
| `--table` | `postgres`, `mysql`, `sqlite`, `dynamodb` |
| `--query` | Custom SQL (overrides `--table`) |
| `--collection` | `firestore`, `mongodb` |
| `--database` | `mongodb` database name |
| `--project` | `firestore` GCP project ID |
| `--database-id` | `notion` database ID |
| `--base-id`, `--table-id` | `airtable` |
| `--sheet` | `excel`, `gsheets` sheet name |
| `--spreadsheet-id`, `--credentials` | `gsheets` |
| `--region` | `dynamodb` AWS region |
| `--addr`, `--password`, `--redis-db` (default `0`), `--pattern` | `redis` |
| `--url` | `elasticsearch` or Confluence API server URL; `croissant` metadata URL |
| `--index` | `elasticsearch` index |
| `--api`, `--space` | `confluence` live API mode and space key |
</Accordion>
</AccordionGroup>

See [Import](/import/overview) for per-source setup.

### query

Run a [DQL](/concepts/dql) query against the index. Run `kiwifs reindex` first if the index is empty.

```bash Terminal
kiwifs query 'TABLE name, status FROM "students/" WHERE status = "active"'
kiwifs query 'DISTINCT status' --format list
kiwifs query 'LIST FROM "concepts/" SORT _updated DESC' --limit 10
```

<Accordion title="Flags">
| Flag | Default | Description |
| --- | --- | --- |
| `--root`, `-r` | `./knowledge` | Knowledge root |
| `--format` | `table` | `table`, `list`, `json`, or `count` |
| `--limit` | `0` | Max results (overrides the query's `LIMIT`) |
| `--sort` | | Sort field (overrides the query's `SORT`) |
| `--order` | | `asc` or `desc` |
</Accordion>


<Accordion title="Flags">
| Flag | Default | Description |
| --- | --- | --- |
| `--root`, `-r` | `./knowledge` | Knowledge root |
| `--group` | | Field to group by (required) |
| `--calc` | `count` | Comma-separated: `count`, `avg:field`, `sum:field`, `min:field`, `max:field` |
| `--path` | | Path prefix to scope results |
| `--where` | | DQL `WHERE` filter expression |
</Accordion>

## Quality and maintenance

### check

CI-friendly scan: janitor hygiene checks, plus sequence gaps in `<!-- seq:N -->` markers when `[sequences]` is configured. Exits `0` when clean, `1` when issues are found, `2` when the scan fails.

```bash Terminal
kiwifs check --root ./knowledge --fail-on-warn
```

<Accordion title="Flags">
| Flag | Default | Description |
| --- | --- | --- |
| `--root`, `-r` | `./knowledge` | Knowledge root |
| `--stale-days` | `90` | Days before a page is considered stale |
| `--json` | `false` | Emit JSON |
| `--fail-on-warn` | `false` | Exit `1` on warnings, not only errors |
</Accordion>

### lint

Validate a knowledge directory against its `SCHEMA.md`: orphans referenced by the schema, broken wiki links, empty files, and a missing schema. Exits `1` if any issues are found.

```bash Terminal
kiwifs lint --root ./knowledge --json
```

<Accordion title="Flags">
| Flag | Default | Description |
| --- | --- | --- |
| `--root`, `-r` | `./knowledge` | Knowledge root |
| `--json` | `false` | Emit JSON |
</Accordion>

### janitor

Scan for hygiene issues: stale, orphan, duplicate titles, contradictions, missing owner or status, empty pages, broken links, missing review dates, decisions in meeting notes, expired memory, and stale runbooks. Exits `1` on error-severity issues.

```bash Terminal
kiwifs janitor --root ./knowledge --stale-days 60 --json
```

<Accordion title="Flags">
| Flag | Default | Description |
| --- | --- | --- |
| `--root`, `-r` | `./knowledge` | Knowledge root |
| `--stale-days` | `90` | Days before a page is considered stale |
| `--json` | `false` | Emit JSON |
</Accordion>

Runbook staleness is opt-in through `[janitor.execution_staleness]` in `.kiwi/config.toml`. See [Configuration](/configuration).

### eval

Measure retrieval quality (Hit Rate, MRR, Precision@K, nDCG@K) for full-text and, when configured, vector search against a golden set in `.kiwi/eval/` (`<name>.qrels` in TREC format and `<name>.topics`). Exits non-zero when a threshold is not met, so it can gate CI.

```bash Terminal
kiwifs eval --list
kiwifs eval --set leave-one-out -x projects/atlas/ --top-k 10
kiwifs eval --set leave-one-out --format json --min-hit-rate 0.6
```

<Accordion title="Flags">
| Flag | Default | Description |
| --- | --- | --- |
| `--root`, `-r` | `./knowledge` | Knowledge root |
| `--set` | | Golden set name under `.kiwi/eval/` |
| `--list` | `false` | List golden sets and exit |
| `--exclude-prefix`, `-x` | | Hide a path prefix from retrieval before ranking (repeatable) |
| `--top-k` | `5` | Rank cutoff for every metric |
| `--format` | `text` | `text` or `json` |
| `--min-hit-rate` | `0` | Fail if the best engine's hit rate is below this |
| `--min-mrr` | `0` | Fail if the best engine's MRR is below this |
| `--min-ndcg` | `0` | Fail if the best engine's nDCG is below this |
</Accordion>

See [Search](/concepts/search).

<Accordion title="Flags">

</Accordion>

### model download

</Accordion>

### restore

Clone a knowledge base from a git remote.

```bash Terminal
kiwifs restore --from git@github.com:org/knowledge.git --to ./knowledge
```

<Accordion title="Flags">
| Flag | Default | Description |
| --- | --- | --- |
| `--from` | | Git remote URL (required) |
| `--to` | | Local directory (required) |
| `--branch` | remote default | Branch to check out |
</Accordion>

### bench

Benchmark single writes, bulk writes, reads, search, and storage overhead in a temporary directory with an in-process stack. Prints a markdown table.

```bash Terminal
kiwifs bench --files 200 --search-files 5000
```

<Accordion title="Flags">
| Flag | Default | Description |
| --- | --- | --- |
| `--files` | `50` | Files for write and read benchmarks |
| `--bulk` | `100` | Files for the bulk write benchmark |
| `--search-files` | `1000` | Files to index for the search benchmark |
| `--search-queries` | `50` | Search queries to run |
</Accordion>

### update

Download the latest `kiwifs` release from GitHub and replace the running binary in place. No flags.

```bash Terminal
kiwifs update
```

Other commands check for a newer version in the background, at most once every 24 hours.

## KiwiFS Cloud

These commands work with hosted workspaces. See [KiwiFS Cloud](/guides/cloud).

### login

Sign in with the OAuth device flow: the CLI shows a code, you confirm it in your browser, and the session is stored in `~/.kiwifs/credentials.json`.

```bash Terminal
kiwifs login
```

<Accordion title="Flags">
| Flag | Default | Description |
| --- | --- | --- |
| `--host` | `https://app.kiwifs.com` | KiwiFS Cloud host |
| `--client-id` | auto-detected | WorkOS client ID override |
</Accordion>

### logout

Remove the stored credentials.

```bash Terminal
kiwifs logout
```

### whoami

Show the signed-in user.

```bash Terminal
kiwifs whoami
```

### connect

Print or write MCP client config for a workspace, with your API key embedded.

<CodeGroup>
```bash Print config
kiwifs connect my-workspace --key kiwi_sk_abc123
```

```bash Write to Cursor (project)
kiwifs connect my-workspace --write cursor --project
```

```bash Write to every detected client
kiwifs connect my-workspace --write auto
```
</CodeGroup>

<Accordion title="Flags">
| Flag | Default | Description |
| --- | --- | --- |
| `--key` | `$KIWI_API_KEY` | API key (optional after `kiwifs login`) |
| `--write` | | Write to a client: `cursor`, `claude-code`, `windsurf`, `claude-desktop`, or `auto` |
| `--host` | `https://api.kiwifs.com` | KiwiFS Cloud API host |
| `--project` | `false` | Write project-level config instead of global (Cursor, Claude Code) |
</Accordion>
